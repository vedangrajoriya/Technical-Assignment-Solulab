## 4. Current Deployment Blockers & Remediations Applied

| Blocker ID | Affected Area | Severity | Description | Remediation Applied |
| :---: | :--- | :---: | :--- | :--- |
| **BLK-01** | Database URL | Critical | Render passes `postgres://` or `postgresql://` without driver tag, causing SQLAlchemy 2.0 to fail with `NoSuchModuleError`. | Added `normalize_database_url` validator in `Settings` to safely convert prefixes to `postgresql+psycopg2://`. |
| **BLK-02** | Security / Logging | High | `database.py` printed raw `DATABASE_URL` during connection exceptions, exposing database password in logs. | Integrated `get_masked_url()` using SQLAlchemy `make_url().render_as_string(hide_password=True)`. |
| **BLK-03** | Frontend API URL | Medium | If `VITE_API_BASE_URL` was supplied without `/api/v1` or with a trailing slash, client requests failed. | Added smart normalizer in `frontend/src/api/client.ts` to ensure clean protocol and `/api/v1` endpoint resolution. |
| **BLK-04** | SPA Routing | Medium | Direct browser refresh on sub-routes in a static site returns 404 without rewrite rules. | Configured Render Blueprint `routes:` with `source: /*`, `destination: /index.html`, `type: rewrite`. |
| **BLK-05** | Migration Architecture | High | Initial Alembic migration revision lacked explicit DDL operations. | Implemented explicit, version-controlled Alembic DDL operations (`op.create_table`, `sa.Column`, `sa.CheckConstraint`, `sa.ForeignKeyConstraint`, `op.create_index`) for all 9 application tables in revision `2e23183d32ef` with safe reverse-order `downgrade()` and idempotency checks. |
| **BLK-06** | CORS Restrictions | High | Backend CORS must accept the deployed Render frontend domain. | Added `https://forgeflow-frontend.onrender.com` to default `CORS_ORIGINS` in `config.py`. |

## 6. Ephemeral Filesystem & Persistence Review

- **Render Web Services:** Ephemeral disk. Any local file written to disk is discarded when instances restart or redeploy.
- **Application State:** 100% of manufacturing records (Orders, Subcontracts, Dispatches, Receipts, Inspections, Invoices, Activity Logs, Users) reside in **PostgreSQL 16**.
- **File Uploads:** The current prototype uses browser-native data forms and mock photo attachments. No binary files are written to the local server disk.
- **Verdict:** Application is **100% cloud-stateless** and fully compatible with Render's ephemeral filesystem architecture.

## 7. Render Free-Tier Constraints & Mitigations

1. **PostgreSQL Database 30-Day Lifespan:**
   - Render Free PostgreSQL databases expire after **30 days**. Render gives a 14-day grace period to upgrade before permanent deletion.
   - *Mitigation:* Documented `pg_dump` and `pg_restore` backup procedures in `RENDER_DEPLOYMENT.md` for seamless monthly instance rollover.
2. **Web Service Spin-Down (Cold Starts):**
   - Free Web Services spin down after **15 minutes of inactivity**. The next request may take 30–50 seconds to boot up.
   - *Mitigation:* Frontend displays responsive loading states and a connection indicator. Health check path `/health` allows automated keep-alive pings if configured.
3. **Pre-Deploy Commands on Free Tier:**
   - Render Free tier does not support `preDeployCommand`.
   - *Mitigation:* Start command executes `python -m alembic -c backend/alembic.ini upgrade head && uvicorn ...`, guaranteeing migrations run before HTTP requests are served. On paid tiers (Starter+), this can be promoted to `preDeployCommand`.
4. **Usage Limits:**
   - 750 free instance hours per month across free web services.
   - 1 GB free PostgreSQL storage (ForgeFlow dataset uses <5 MB).
